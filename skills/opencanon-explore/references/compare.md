# 只读对照代码

步骤 2 读。只在会话里标号，不写盘、不 `edit`、不问人。对照回答：该命中的 `body` 是否仍是项目现状。

## 证据

独立证据是该原子 `impl-path` 里每一个文件（相对被治理项目根的代码或配表）。代码/配表是现状；有对应 `.rs` / 配表时不要用 `AGENTS.md` 当 path。

打开其中每一个路径。只核 body 中归该文件的分块：文件 A 证明块 A，不用 A 去证明块 B。列表里任一路径读不到：该条标 `无法对照`。无 `impl-path`（缺省、空白、或列表空）：标 `无法对照`。

三分只来自这些文件。

## 三分

对打开的实现与该命中的 `body` 只标一种：

- **一致**：每个分块与对应文件同宽，可逐条对上，且代码没有相反行为
- **不一致**：两边都有可核对的事实，但某块与其文件主张相反，或代码明确没有该块所声称的机制
- **无法对照**：读了仍对不上——某块相对其文件既不能证实也不能证伪，或文件读不到

## 观察

问题需要实现上下文时（机制怎么串、结合代码看现状）：以本条已打开的 `impl-path` 为种子，沿引用或同模块只读扩一圈。只核该条是否仍成立、不需要串上下文时，不扩圈。

扩圈所得、以及零命中搜到的代码，都是观察：不把邻文件当作另一块的证据，不因此改三分。不为了解项目扫全库。

完成：每个相关命中是 `一致`、`不一致` 或 `无法对照`；每个标号都来自已读到的 `impl-path` 文件内容（或明确读不到 / 无路径）。
