# 拆分

步骤 1 对照抽出例；步骤 2 对照合稿例与通写例。每组是「源片段 → 候选」。

## 标题是骨架

源：

```markdown
## 1. 要解决的问题

1. **越写越重复** —— 同一事实被复制/改写进多篇文档，改一处漏多处，逐渐失同步。
```

候选（一条）：同一事实被复制进多篇，改一处漏多处。

不是「第1节标题为要解决的问题」。

## 命令规格节

源：

````markdown
## `opencanon get <id>`

### 功能

按 id 读出单个原子的完整内容（含 `body`）。任意 `status` 均可读。不改磁盘。

### 成功示例

```
$ opencanon get durability_daily_restore
```

```json
{
  "atom": {
    "id": "durability_daily_restore",
    "status": "draft",
    "title": "禁军突围装备耐久恢复机制",
    "body": "正文：只描述一个事实。"
  }
}
```
````

候选（一条）：`opencanon get` 按 id 读出完整原子（含 body），任意 status 可读，不改磁盘。

成功示例里的命令行和 JSON 不成候选。约束若落在多个实现文件，仍是这一条：body 按文件成段，`impl-path` 列出那些路径。不要拆成多条原子，也不要因为某一个文件盖不全整篇而省略 path。

## body 按实现文件分块

源（一条命令主张，落地在两个文件）：

```markdown
`opencanon freshness [id...]` 对 active 原子打分写回 score。无 impl-path 则 skip。
clap 用法错误退出码 2、无信封。
```

归属：仍一条（读者当一个命令问题来查）。通写：按文件成段，每段约束只陈述该文件负责的事实；`impl-path` 列出 `commands/freshness.rs` 与（仅当本条确实主张退出码且尚未被全局约定原子覆盖时）对应 CLI 入口文件。

不是「freshness.rs 一条、lib.rs 一条」。不是省略 path。全局 clap 退出码若已是另一条原子的事实，本条不重复。


## 表行同决策

源：

| 角色 | 职责 | 不做的事 |
|------|------|----------|
| **Skill** | 定义流程调用顺序、参数、prompt 策略、人工确认卡点 | 不含业务逻辑 |

候选（一条）：Skill 负责编排（流程顺序、参数、prompt、人审卡点），不含业务逻辑。

不是五条各写一句职责。一行仍是一条；多行若是同一决策的原则、形态、手续，见下节。

## 原则与落地

源：

```markdown
核心思想：一处事实只在一处记录，其他地方只引用、不复制。
引用形式：链接跳转而非复制正文。
```

归属：一条。通写（一条）：OpenCanon 一处事实只记录一次。其它文档用链接跳转引用、不复制正文。

不是「SSOT 原则」一条、「用链接」一条。停在「一处记录 + 链接不复制」。

「新增文档：先查无真源再写；已有则只加链接」归查重机制，不并进 SSOT。

不是把理念表里查重、拼接、新鲜度等会被分开来问的机制并成一条。

## 清单与机制

源：

```markdown
分工原则：确定性归工具，语义判断归 LLM，流程编排归 Skill。
CLI 不做语义判断；LLM 不做确定性计算；Skill 不含业务逻辑。
CLI 职责还包括扫描、查询检索、落盘、拼接、新鲜度元数据信号、查重召回。
查重：字面宽召回，agent 判是否同一事实。同则复用、不新建。
```

归属：两条（分工是职责清单，查重是会被分开来问的机制）。

通写：

- OpenCanon 确定性归 CLI、语义归 LLM、编排归 Skill；CLI 不做语义判断，LLM 不做确定性计算，Skill 不含业务逻辑。
- 查重用字面宽召回加 agent 精判是否同一事实；同则复用、不新建。

清单那条只留原则与互斥边界。角色表三行仍合成这一条。「查重召回」只出现在查重那条。

## 通写

源：同「原则与落地」。归属：一条。

拼装：一处事实只记录一次；其他地方用链接引用。

通写（一条）：OpenCanon 一处事实只记录一次。其它文档用链接跳转引用、不复制正文。

通写是一篇「事实写在哪、怎么引用」，不是把并入片段按原文顺序用分号接起来。先查后写见查重机制，不写进这一条。

## 删句

源：

```markdown
查重用字面宽召回（宁宽勿漏）。
字面召回只抓近重复；宽召回加 agent 精判可缓解。
误报成本低，漏报成本高，所以阈值宁宽勿窄。
```

归属：一条。

拼装：「宁宽勿漏」从思路、边界、成本各说一遍。

通写（一条）：漏报贵于误报，故字面宽召回（只抓近重复），再由 agent 精判是否同一事实。

删去任一句子后，本条少一个约束或因果环节。同一理由只写一次。

## 未决并入机制

源：

```markdown
查重用字面宽召回，再由 agent 判定是否同一事实。
开放问题：同一事实的判定标准；字面漏召时是否用语义方法补。
```

归属：一条（未决是查重的尾巴）。通写（一条）：查重用字面宽召回加 agent 精判是否同一事实；同则复用、不新建。同一事实的判定标准、以及措辞不同时要不要用语义补召，仍开放。

不是「查重」一条、「开放问题」清单一条。

## 连接句只留一处

源：

```markdown
安全模型：原文档只读，产出落独立目录。该目录可随时整个删了重来。
终态定位：真源目录成为新权威。工具是迁移引擎，旧目录退化为历史归档。血缘迁完后不追踪。
```

归属：两条（读者会当两个问题来查）。

通写：

- OpenCanon 把旧文档迁成原子真源：不改写主张正文，产出落独立真源目录，该目录可整份删除后重来。
- 真源目录逐步成为新权威，旧目录退化为历史归档；迁移完成后不长期追踪血缘。

「成为新权威」只出现在后一条。一次迁不完、已迁标记等手续并入前一条，见「迁移手续并入」。

## 后文复述

源：

```markdown
作为对外产品要降预期，建议先自己用、验证有效再考虑通用化。

建议路径：先为自身项目做出可用版本并真正用起来，再提炼通用层对外。
```

候选（一条）：对外产品降预期，路径是先自用验证再提炼通用层。

不是「降预期」一条、「先自用再通用化」一条。

## 跨节因为所以

源：

```markdown
最大风险是被「把文档丢给 RAG 直接问答」替代。

RAG 不保证唯一真源，会从重复或过期文档给出矛盾答案。若能证明经真源治理后 AI 问答更准，则可定位为 AI 知识库的前置治理层。
```

候选（一条）：精细原子化面临被 RAG 问答替代的风险；因 RAG 不保证唯一真源，故定位为给 AI 准备干净真源的前置治理层。

不是风险一条、定位一条。

## 收束句

源：

```markdown
最大风险是被 RAG 问答替代。RAG 不保证唯一真源，故可定位为 AI 知识库的前置治理层。

没有四合一开源项目；近邻只做漂移或新鲜度。缺口在组合流水线。
```

归属：两条（读者会当两个问题来查）。

通写：

- 精细原子化面临被 RAG 替代的风险；因 RAG 不保证唯一真源，故定位为给 AI 准备干净真源的前置治理层。
- GitHub 实测（非穷举）没有对等的四合一项目；近邻分别只做漂移与新鲜度，缺口在组合流水线。

「前置治理层」只出现在前一条。后一条写完「缺口在组合流水线」即停。

## 调研快照

源：

```markdown
没有把「原子真源 + 查重 + 拼接 + 新鲜度」组成完整流水线的对等项目。
项目甲（2 stars）只做漂移检测；项目乙（0 stars）只做新鲜度。
二者极冷门，说明细分热度低；差异化放在组合而非单点轮子。
```

候选（一条）：截至源文档 v0.3 的 GitHub 实测（非穷举）没有对等的四合一项目；近邻分别只做漂移与新鲜度且极冷门，故热度低但痛点真实，缺口在组合流水线。

不是「没有四合一」一条、项目各一条、热度一条、差异化一条。

## 迁移手续并入

源：

```markdown
把旧文档迁成原子真源，而不是原地改写。原文档只读，产出落独立目录。
旧文档不可能一次迁完。已迁的标记已迁移，未迁的保持原样。
血缘只在迁移时有用，迁完后真源即唯一权威，工具不长期追踪血缘。
```

归属：两条（怎么迁 vs 迁完后谁是权威）。

通写：

- OpenCanon 把旧文档迁成原子真源，而不是原地改写。原文档不改写主张正文，产出落独立目录。一次迁不完：已迁的标记为已迁移，未迁的保持原样。
- 迁移完成后真源成为唯一权威，旧目录退化为归档；血缘只在迁移过程中有用，工具不长期追踪。

不是「只读」一条、「分批标记」一条、「权威与血缘」一条。分批是怎么迁的手续，并入先出现的那条。

## 痛点落到故

源：

```markdown
查找困难 —— 找不全、找不准。
不做全局索引。索引是第二份事实，极易腐坏；按需扫描原子的元数据与正文。
```

归属：一条。通写（一条）：文档会找不全、找不准，故 OpenCanon 不养全局索引（索引是第二份事实、易腐坏），改为按需扫描原子。

不是「不做索引、按需扫描」之后再挂一句「文档增长后会找不全」。痛点落到「故」后的约束，不写成新机制的性质。
