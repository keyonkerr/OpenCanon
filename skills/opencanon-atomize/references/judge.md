# 对照代码判定

步骤 3 判同之后、提问之前读。只在会话里标号，不写盘。本篇源文档不是证据：源是待入库的主张，不能用来证明自己。

独立证据是当前代码事实（打开 `impl-path` 里每一个文件）和已有 **active** 真源。和谐不等于真实；能被已有 `body` 覆盖的，步骤 3 应标 `same`。代码/配表是现状；有对应 `.rs` / 配表时不要用 `AGENTS.md` 当 path。

## 范围

本批要处置且带 `impl-path` 的：

- 步骤 2 已填路径的候选（含判同为 `unsure` 的：人选 `different` 时沿用本步的 `true` / `false` / `ask`）
- 已标 `same <id>` 的命中（含 **active**）
- `unsure` 题干将列出的、带 `impl-path` 的 hit（人选 `same_<id>` 时沿用，避免写盘前再开一轮）

不扫全库。不改仅关键词命中、判为 `different` 的原子。列表里任一路径读不到：该条无法对照，标 `ask` / `ask_edit`。

## 读实现

用读文件能力打开 `impl-path` 中**每一个**路径（相对被治理项目根的代码或配表）。只核 body 中归该文件的分块：文件 A 证明块 A，不用 A 去证明块 B。不要靠邻文件给另一块补证据。

某块对不上其文件 → 该候选不一致或无法对照。不要因此把整条拆成两条原子。

填了路径、文件在、或步骤 2 已查找过，都不算已判定。

## 三分

对打开的实现与正在核的那篇 `body`（候选或已有原子）只标一种：

- **一致**：每个分块与对应文件同宽，可逐条对上，且代码没有相反行为
- **不一致**：两边都有可核对的事实，但某块与其文件主张相反，或代码明确没有该块所声称的机制
- **无法对照**：读了仍对不上——某块相对其文件既不能证实也不能证伪，或文件读不到

问题 / 市场 / 调研、无代码的产品决策：无路径，不进本步。

`false` 只表示与代码事实不一致。骨架、比喻、命令演示若还在本批里，回到步骤 1–2 并入所属主张或从本批拿掉。

与某条 **active** 原子互相矛盾、又不是步骤 3 的 `same`：标 `ask` / `ask_edit`，不要只凭代码转正把真源写成两套相反约束。

## 候选落点

将要新建的（`different`、无命中；以及 `unsure` 且人选 `different`）：

| 三分 | 标号 | 写入 |
|------|------|------|
| 一致，且不与 active 真源冲突 | `true` | `add` 再 `active` |
| 不一致 | `false` | 不创建 |
| 无法对照 | `ask` | 问人 |

禁止把「不确定」写成静默 `draft`。`uncertain` 只来自人的选择。

## 已有原子落点

已确定 `same <id>` 的命中（含人选 `same_<id>`）：

| 情况 | 标号 | 写入 |
|------|------|------|
| 已有 `body` 各块与对应文件一致 | 不动 | 不 `edit` |
| 已有 `body` 与代码不一致 | `auto_edit` | 按代码事实改 `body`（分块与 path 列表对齐） |
| 候选有现有 `body` 没有的细节，且那些细节与对应文件一致 | `auto_edit` | 通写后的整篇主张写入 |
| 候选新细节与代码不一致 | 不动（对该细节） | 不要把与代码不符的源细节写进真源 |
| 读了仍无法对照，或有新细节但对不上代码 | `ask_edit` | 问人 `edit` / `keep` |

命中是 **draft** 且候选（或已有 `body`）与代码一致：标 `true`，写入时对该 `id` `active`。draft 无法对照：标 `ask`。

## 无路径

没有 `impl-path` 的新建或 draft 复用：一律 `ask`。`same` + active + 无路径 + 无新细节：不动。`same` + 无路径 + 有新细节：`ask_edit`。

完成：每个带路径的候选是 `true`、`false` 或 `ask`；每个须核的 `same` / 待选 `same` 命中是不动、`auto_edit` 或 `ask_edit`；每个标号都来自已读到的文件内容（或明确读不到）。
